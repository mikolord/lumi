# Задание: приложение Lumi для Windows

Нужно довести до проверяемого установщика Windows-приложение Lumi с автоматической
загрузкой фотографий и видео из выбранных пользователем папок.
Не ограничиваться макетом, планом или ярлыком браузера: результат — работающая
программа, исходники, воспроизводимая сборка, тесты и публичный выпуск GitHub.

## Общая база и координация

- Репозиторий: https://github.com/mikolord/lumi, общая ветка `main`.
- Сначала обнови `origin/main` и прочитай [RELEASING.md](RELEASING.md),
  [README.md](README.md), этот файл и исходники `android-tv/`.
- ПК-интерфейс исправлен в серверном выпуске 0.76.2: выделение диапазонов,
  контекстные меню, поиск людей, панель просмотра под изображением, плотность альбомов.
  Не возвращай прежнюю ПК-компоновку и не переписывай рабочий мобильный интерфейс.
- Работай в отдельной ветке/worktree. Перед отправкой объедини изменения свежей `main`.
  Не делай force-push, не перезаписывай существующие релизы и ключи Android.
- Windows-код размещай в `windows/`. Переделка серверного API допустима только
  при доказанной необходимости, с обратной совместимостью и тестами.

## Архитектура

Сделай полноценный Windows-хост с WebView2 для уже готового интерфейса Lumi и
нативными файловой очередью, наблюдением за папками, треем, настройками и установкой.
Так сохраняется одна версия интерфейса на сервере, а работа с файлами не зависит
от ограничений браузера. Это тот же принцип, который уже реализован в Android.

Базовый вариант: C#, WPF, .NET 10 LTS, WebView2 Evergreen и SQLite.
Проверь совместимость используемых пакетов по официальной документации.
Основная сборка — Windows x64; Windows 11 обязателен, совместимость с Windows 10
22H2 укажи только после реальной проверки. ARM64 — отдельный проверенный артефакт,
если есть возможность его собрать и проверить. Самостоятельно не обещай macOS/Linux.

Официальные источники:

- [.NET support policy](https://dotnet.microsoft.com/en-us/platform/support/policy)
- [WebView2 for WPF](https://learn.microsoft.com/en-us/microsoft-edge/webview2/get-started/wpf)
- [Distribute WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)
- [WebView2 security](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security)

## Вход и интерфейс

1. При первом запуске — аккуратный экран Lumi, адрес собственного сервера,
   проверка подключения, затем обычный вход по логину и паролю в интерфейсе сервера.
   Сервер Docker обязателен, общего облака нет. QR не нужен для входа на ПК.
2. Сохрани функции веб-версии: фото, видео, альбомы, люди, поиск, редактор,
   выбор нескольких файлов, сохранение, удаление с подтверждением, защищённые разделы.
3. Добавь в профиль пункт «Приложение Windows»: папки автозагрузки, очередь,
   кэш, фон/трей, запуск вместе с Windows по выбору и обновления приложения.
4. Системные выбор файлов/папок, drag-and-drop файлов, «Сохранить как»,
   открытие папки результата. Длительные операции не блокируют интерфейс.
5. Изменение размеров окна, масштаб Windows 100/125/150/200%, светлая и тёмная темы.
   Сохрани миниатюры просмотра, клавиатуру, мышь и прокрутку по датам.

## Автозагрузка папок — обязательная функция

- По умолчанию выключена. Пользователь явно добавляет одну или несколько папок,
  выбирает рекурсивный обход и «только новые» либо «также существующие файлы».
  Не сканируй весь компьютер и не включай запуск вместе с Windows без выбора пользователя.
- Фото и видео в поддерживаемых сервером форматах; учитывай HEIC/HEIF там,
  где они поддержаны сервером. Не загружай временные файлы и незавершённые копии.
- FileSystemWatcher служит сигналом. Нужны также сверка при запуске/возврате из сна,
  периодическая сверка и восстановление после переполнения буфера наблюдателя.
- Проверяй стабильность размера/времени изменения перед чтением; повторяй позже,
  если файл занят, ещё копируется, диск отключён или OneDrive-файл пока недоступен локально.
- Не скачивай автоматически всю облачную папку OneDrive ради обхода: показывай,
  какие файлы недоступны; политика загрузки облачных файлов должна быть явным выбором.
- Очередь SQLite переживает закрытие, сон, сбой сети и перезапуск. Задания разделены
  по нормализованному адресу сервера и подтверждённому ID аккаунта.
- Для каждого файла показывай состояние, прогресс, причину ошибки и повтор.
  Нужны общие количества: ожидают / загружены / уже существуют / ошибки,
  пауза и продолжение, повтор ошибок, отмена выбранного задания.
- Ограничь число параллельных передач. Читай и хешируй потоком, без загрузки
  гигабайтного видео целиком в память. Пауза, выход из аккаунта и смена сервера
  останавливают текущие передачи и не позволяют отправить данные другому пользователю.
- Используй проверку SHA-256 до передачи, постоянный идентификатор загрузки
  и проверку завершённой операции после потери ответа. Уже существующие на сервере
  файлы повторно не передавай. Сохраняй историю проверки после очистки завершённой очереди.
- Перемещение или переименование файла не должно бессмысленно загружать его заново.
  Изменившийся файл проверяется как новая версия. Объясни используемую стратегию.
- Автозагрузка только добавляет файлы. Удаление/перемещение на компьютере
  не удаляет оригиналы на сервере и наоборот. Не добавляй двустороннее зеркало.
- Фоновая работа — через запущенное приложение/трей. Закрытие окна, полный выход
  и запуск с Windows должны быть понятными отдельными настройками.
  После перезагрузки без включённого автозапуска не обещай фоновую работу.

## Реальный API, авторизация и безопасность

Посмотри `MobileUploadTransport.kt`, `MobileAccount.kt`, `MobileUploads.kt`,
`MobilePolicy.kt`, `assets/mobile-native.js` внутри `android-tv/app/src/main/`.
Сверь контракт с `server.py`, `accounts.py` и `upload-queue.js` — не выдумывай API.
Уже существуют `/api/account/status`, `/api/assets/upload-status`,
`/api/assets/check`, `/api/assets/upload`.

- Используй настоящую аккаунтную сессию WebView2, CSRF и проверку владельца
  перед фоновой отправкой. Пароль приложения отдельно не сохраняй.
- Передавай только необходимые account/CSRF cookies; не копируй vault-cookie
  защищённых альбомов в загрузчик. Учётные данные храни через средства Windows
  с привязкой к текущему пользователю. Не сохраняй их в открытом JSON/логах.
- Нативный мост разрешён только главному фрейму точного настроенного origin.
  Не открывай произвольный путь/команду по строке из JavaScript. Файловые операции
  используют пути, выбранные в нативном диалоге, или собственные ограниченные каталоги.
- Внешние ссылки открывай браузером. При редиректах не отправляй сессию другому
  origin. Не отключай проверку HTTPS-сертификатов. HTTP допускается для домашнего сервера.
- При смене аккаунта, сервера, отзыве сессии и полном выходе убирай доступ
  к прежней очереди/кэшу. Защищённые разделы блокируй при новом запуске.
- При импорте и сохранении не меняй и не удаляй исходные файлы компьютера.

## Кэш миниатюр

Постоянный ограниченный по размеру дисковый кэш, повторное использование после
перезапуска, обновление при изменении содержимого/обложки. Не отключай готовый
кэш PWA и не добавляй блокирующую загрузку всей библиотеки перед показом.
Запрашивай в первую очередь видимую область. Нужны очистка и настройка лимита.
Соблюдай проверки доступа и изоляцию аккаунтов. Не кэшируй защищённые оригиналы.
Если достаточно существующего кэша WebView2/PWA, измерь это и используй его,
а не создавай второй независимый набор всех миниатюр. Офлайн-режим не обещай
без отдельной реализации и тестов.

## Установка и обновления

- Подготовь воспроизводимую сборку и установщик для текущего пользователя.
  При необходимости WebView2 Runtime используй официальный механизм Microsoft.
- Публичные файлы GitHub Releases: установщик, SHA-256, манифест версии,
  описание изменений. Версии Windows независимы от сервера и Android.
- Используй теги `windows-vX.Y.Z` и `make_latest=false`: `/releases/latest`
  остаётся серверным выпуском. Отдельный Windows-манифест, а не `tv-updates`.
- Кнопка «Проверить обновления» скачивает напрямую из публичного GitHub,
  показывает прогресс и причину ошибки, проверяет контрольную сумму и применимость
  версии до запуска установщика. Ключи/токены в программу и репозиторий не включать.
- Документируй подпись артефактов. Если доверенного сертификата нет, честно укажи
  отсутствие подписи и ограничения; не выдавай самоподпись за доверенную и не обходи SmartScreen.
- Обновление сохраняет настройки и очередь. Удаление программы не трогает
  серверную библиотеку и исходные папки пользователя.

## Критерии приёмки

Покажи результаты проверок на отдельном тестовом аккаунте и синтетических файлах:

1. Установка на чистую Windows, вход, просмотр, альбомы, поиск, видео и выделение.
2. Первичная загрузка выбранной папки; новый файл в ней загружается автоматически.
3. Повторный запуск и переименование не создают дубли; очистка очереди не приводит
   к повторной передаче всей папки.
4. Потеря сети во время передачи, сон/пробуждение, аварийное закрытие и повторный
   запуск восстанавливают очередь. Завершённый сервером файл распознаётся без дубля.
5. Файл в процессе копирования, занятый файл, недоступный диск, большой видеофайл
   обрабатываются без зависания и потери данных.
6. Смена аккаунта/сервера и отзыв сессии не отправляют ни одного задания прежнего
   аккаунта новому. Внешний фрейм не может вызвать файловый мост.
7. Проверка, скачивание и установка следующей тестовой версии без потери настроек.
8. Реальные измерения памяти и повторных загрузок миниатюр на большой библиотеке;
   не заявляй «всё летает» только по unit-тестам.

В конце дай ссылки на коммит и релиз, установщик, инструкцию запуска/автозагрузки,
прошедшие тесты и честный список ограничений. Не меняй настройки живого сервера
и не сканируй реальные личные папки ради теста. Перед публикацией повторно
проверь свежую `main` и сохрани изменения других разработчиков.
